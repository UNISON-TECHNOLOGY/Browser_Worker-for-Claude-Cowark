# 一括送信の実行規範（正本）

> スカウト・投稿・配信・入稿など**不可逆な送出をN件まとめて行うとき**に読む。ゲート（bulk_send → psv_done → ov_done）は
> [../steps-reference.md](../steps-reference.md) の Step F/H/I が正本で、ここは**実行体の組み立て方**の正本。
> 出典は元リポジトリの実弾スクリプト（判定ロジックのみ移植。Playwright/CDP 依存の実装は移植しない → [freeze.md](freeze.md)）。

## 1. DRY-RUN が既定

- 実行体（凍結スクリプト / `javascript_tool` / `browser_batch`）は**必ず dry-run を既定**にする。dry-run の役割は「**誰に何を送るか**」の確定 = 対象リストの表出力のみ。DOM 変更・送信操作を1つも起こさない
- 実送信は**明示フラグ相当の承認**（ユーザーが「送って」と言い、Step H の監査と承認が揃った状態）のあとだけ。既定を「送る」にしたスクリプトを書かない
- dry-run の出力表 = pre-send-verifier に渡す確定対象表 = 事後照合の材料。3つを別々に作らない

## 2. コミット枠管理（送信上限）

- 上限（N件）は「**送信操作を発行した時点**」で1枠消費する（成功確認の前にコミット）。停止条件は成功数ではなく**コミット枠数**
- こうすると成功判定が偽陰性でも別候補を繰り上げず、リトライで上限を超えない。**失敗した候補の枠は返さない**
- 終了時に「コミット枠数 / 上限 / 成功記録数 / 残数の実減少」を並べて報告する。**不一致は警告として明示**（偽陰性・遅延の疑いを黙って飲まない）

## 3. 二重シグナルの成功判定

- 成功は**独立した2つのシグナル**（例: 完了トースト + 残数/チケットの減少）が揃ったときだけ。「ボタンを押せた」は成功ではない
- 片方しか取れない場合は短時間だけ他方を待ち、それでも揃わなければ「**不明**」として**停止し人間に報告**（成功にも失敗にも丸めない）
- 送信前に残数が読めない = 成功を検証できない → **送らずに中断**する
- 画面の残留エラーテキストで実シグナルを打ち消さない／実シグナルが1つも無いときだけエラー文言を失敗理由に採る

## 4. 回路ブレーカ

- 同種の失敗（パネルが開かない・要素が出ない等）が**連続 N 件**（既定3）で発生したらセッション劣化と判断し、**その場で全体を中断して人間へ報告**。続行・自動リカバリはしない
- 中断時は残り対象・コミット枠・証跡（ログ行 / スクリーンショット）を残す

## 5. レート制御

- 連続送信は**1.2 秒以上 + ランダム待機**（人が操作する程度の間隔）。固定の長 sleep より「短い wait + 状態確認の反復」を使う（[speed.md](speed.md) §5）
- ページ送りを大量に回さない。一覧の取得は1コール集約（speed.md §1）

## 6. 判定は緩めない

- **実行中に CP（適合判定）の基準を変更しない**。基準を変える必要が出たら**中断してユーザーの再承認を取る**（その場の緩和は誤送信そのもの）
- CP 不合格はスキップし、どの CP がなぜ落ちたかをログに残す（0件になっても基準を下げて件数を作らない）
