# 手順の凍結（読み取りはフェーズ②から / 変更はフェーズ④から）

> `docs/steps-reference.md` から分離（2026-07-27）。**必要なときだけ読む**（内容の移動のみ）。

## G'. 手順の凍結

フェーズ④の次段。1要素ごとの LLM 往復を消す。**凍結手段は `javascript_tool`（ページ内JS）と
`browser_batch`（束ね）の2つだけ** — Playwright / CDP(9222) は Cowork に存在しない。
**既存の Playwright/CDP 資産を「移植」しようとしないこと**（使えるツール16本の一覧・
batch の制約・移植を試みた事故の記録は docs/rationale.md）。

凍結先は2つに分ける（bash とブラウザは別マシン。delve-start 0.5）:

| | 置き場所 | 実行 | 中身 |
|---|---|---|---|
| DOM 側 | `knowledge/sites/<site>/snippets/<用途>.js` | `javascript_tool` | 一括抽出（→JSON）・一括入力・一括操作 |
| 判定側 | `scripts/<タスク名>.js` または手順内の計算 | サンドボックスの bash | 適合判定・許可リスト照合・重複除外・上限管理 |

**判定側は純粋計算なので他環境からそのまま救出できる。移植不能なのは DOM 側だけ**（丸ごと捨てない）。

**ローカルでこれが主経路になる根拠**（steps-reference Step G の1行の裏付け）: ローカルは hooks 不発（E4）で機械ゲートが効かないため、1操作ごとの LLM 判断は誰も止めてくれない。dry-run 出力が承認材料になり実行内容を事前に読める凍結スクリプト経由は、往復コストだけでなく**安全面でも**ローカルの既定経路になる。

**凍結の条件は2段**（読み取りと変更で分ける。凍結ゼロで①②を丸ごと見送ると、最も効く読み取りの高速化が
毎回捨てられる）:

| 種別 | 着手できる条件 |
|---|---|
| **読み取り凍結**（一覧抽出・状態取得の `snippets/*.js`） | **フェーズ②（1回成功後）から着手可**。追加条件は**ミューテーションを一切含まないこと**（抽出・集計・突合のみ。click / form_input / 送信・保存を1行も書かない） |
| **ミューテーション凍結**（送信・変更操作） | 従来どおり全て満たす: フェーズ④到達 / **直近2回以上同じ手順で成功** / ランドマークが安定 |

読み取り凍結を先に入れても Step E / I / J と承認は省略しない（速くするのは読み取りであって承認ではない）。
**凍結前（①②）でも1コール集約はできる** — 一括JS・batch の速度規範は [speed.md](speed.md) が正本。

**作り方**:

1. **読み取りから凍結する** — 一覧の全項目を1コールで JSON 化（N回の read_page が1回になる。ここが最も効く）
2. 抽出 JSON を判定側に通し**対象リストを表で出す** = dry-run 出力 = Step H の監査入力
3. **ミューテーションは既定で起こさない**（明示の実行指示があったときだけ）
4. **ゲートを判定側に内蔵**（CP=E-3 / 上限 / 履歴突合 / F-4）。DOM 側は承認済みリストを実行するだけ
5. 送信・保存は1件ずつ、または batch でも**CP5 を1件ずつ確認できる形**にする
6. dry-run 1回・実行1回を実機検証してログに記録し、サイトナレッジに凍結済みと1行書く

**凍結後**: Step E / I / J とユーザー提示・承認は従来どおり省略しない。
セレクタ不一致で落ちたら**フェーズ③へ戻る**（勘で直さず再マッピングしてから凍結し直す）。
