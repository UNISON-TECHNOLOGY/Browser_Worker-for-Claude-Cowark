# /メモリ圧縮 — session-log・ナレッジの構造化圧縮（delve-memory）

肥大化した記録を、検索可能な構造化データに圧縮する（内容は捨てず、粒度を変える）。

## 手順
1. 対象を確定（引数: session-log | logs | all。省略時は session-log）
2. session-log: 古いセッション節（直近3セッションより前）を「1セッション=1行サマリー + 学びの箇条書き」に圧縮し、memory/session-archive.md へ移動。session-log 本体には直近分と引き継ぎのみ残す
3. logs: knowledge/logs/ の YAML フロントマターを knowledge/data/delvework.db（SQLite）に取り込み、本文が冗長なログは要点化。DB が無ければ templates/db-schema.sql で初期化
4. 圧縮前後の行数・ファイル数を報告。削除は行わない（アーカイブ移動のみ。破壊的変更はユーザー承認後）
5. 圧縮結果を session-log に1行記録

## 読み込み範囲（引き継ぎ時に読む量）

- **session-log は末尾から直近3セッション分だけを読む**（全文 Read しない。引き継ぎに必要なのは直近の学びと未完了事項で、それ以前は圧縮済み or `memory/session-archive.md` にある）。特定の過去事例を探すときだけ Grep で該当箇所を狙い撃ちする
- session-start hook が **400行超で「/メモリで圧縮を検討」を1行通知**する。通知が出たら本手順で圧縮し、直近3セッション + 引き継ぎだけが本体に残る状態へ戻す

## 圧縮時の保存必須リスト（これが残らない要約は失敗）

どの対象を圧縮するときも、以下は**必ず原文の粒度で生き残らせる**（外部知見: 要約の代償は忠実性）:

1. **決定事項**（ユーザーが決めたこと・採用/不採用の判断と理由）
2. **発見した制約**（レート制限・画面の罠・規約上の線引き・実測値）
3. **ファイルパス・ID**（触った/作ったファイル、対象サイトの URL・タスク名）
4. **未解決の質問・引き継ぎ事項**（次の担当者が最初に見るべきこと）

## ホットパス（1タスクが読む量）の圧縮

**総量を減らしても読む量は減らない** — アーカイブ移動はディスク上の総量を減らすが、
index が両方を指していれば1タスクの読み込みは同じまま。`all` / `logs` を対象にしたときは、
あわせて以下を確認する（docs/steps/knowledge.md の「種別」「有効条件」「index はルーター」）:

1. `kind: log` の内容（消費履歴・実績表・セッション記録）が、ポリシーや操作手順のファイルに
   混ざっていないか。混ざっていたら `knowledge/logs/` へ**内容の移動のみ**で分離する
2. `index.md` に**タスク別・読むファイル表**（ルーター）があるか。無ければ作り、あれば実態と合わせる
3. `kind: operation` の `requires:` が現環境で満たせるか。恒久的に満たせないものは、
   手段非依存の知識（セレクタ・判定順・事故防止ルール）を現行ファイルへ救出してから `_archive/` へ

## 原則
- 事実の消失禁止 — 要約で残す。判断根拠（なぜそうしたか）を優先保存
- フェーズ判定（B-4）が参照する成功ログは圧縮対象外（直近の成功証跡は原文維持）
